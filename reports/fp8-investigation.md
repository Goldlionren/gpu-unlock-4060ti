# FP8 stock numerical investigation

Actual host results: `logs/fp8-investigation.json`, generated by `scripts/investigate_fp8.py` using existing PyTorch/CUDA and no unlock.

At N=2048, Gaussian E4M3 operands have relative L2 error 1.025e-4 with fast accumulation disabled. Enabling it raises error to 8.005e-4. Splitting K into 32-element products and summing their FP32 outputs reduces error to 3.536e-5. Removing FP8 subnormals still leaves 7.470e-5 error. Small dyadic inputs give zero error. At N=256, CPU and GPU FP64 references agree exactly, and changing operand scales to 0.5 and 0.25 gives exactly 0.125 times the original output.

These experiments rule out a simple scale mismatch or CPU/GPU reference disagreement for the exercised cases. Quantization error relative to original floats is excluded because references use already quantized operands. Subnormal handling alone does not explain the residual. Dependence on accumulation chain length and fast accumulation supports accumulation precision/rounding as the explanation; individual SASS instructions have not yet been traced, so this is an evidence-based attribution, not proof of a particular internal mantissa width.

NVIDIA documents that disabling FP8 fast accumulation periodically promotes intermediate results to higher precision; it does not promise equality to a sequential full-FP32 reference. See [CUDA 13.0 cuBLAS documentation](https://docs.nvidia.com/cuda/archive/13.0.0/pdf/CUBLAS_Library.pdf) and [NVIDIA CUTLASS discussion](https://github.com/NVIDIA/cutlass/issues/1329). The original strict numerical threshold remains recorded as failed; it was not relaxed. For unlock acceptance, rerun the same data and compare error statistics and exact dyadic checks, separately from speed. No unlocked result is available yet.

E5M2×E5M2 is rejected by the installed PyTorch operation. This does not establish that every mixed E5M2/E4M3 hardware instruction is unsupported. No alternate precision is silently substituted.
